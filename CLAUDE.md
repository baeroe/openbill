## Was openbill ist

Offenes, selbst gehostetes Programm für Angebote, Auftragsbestätigungen, Rechnungen und Stornos mit eigenen Feldern, eigenen Liquid-Templates (Rendering nur serverseitig, PDF über Gotenberg) und E-Rechnung (EN 16931). Steuerbar über UI, REST-API und MCP. Stand: alle 11 Phasen des Master-Plans umgesetzt, v0.1.0 vorbereitet (UI mit Übersicht, Dokumenten, Kunden, Dokument-Editor, Templates mit Editor und Toolkit, eigenen Feldern und Einstellungen inkl. Benutzerverwaltung und „API & MCP“; REST-API unter `/api`; MCP-Server unter `/mcp`; Docker-Image + Compose-Stack; Doku auf GitHub Pages).

## Regeln

- **Actions-Regel:** Keine Geschäftslogik in Controllern, API-Processors oder MCP-Tools. Abläufe nur in `app/Actions`, Rechnen/Regeln nur in `app/Domain` (reines PHP). Controller validieren, rufen eine Action, formen die Antwort. Architekturtests in `tests/Unit/ArchTest.php` sichern das ab und wachsen mit.
- **pnpm-Regel:** Nur pnpm, nie npm/npx (Einmal-Tools `pnpm dlx`). Root-Abhängigkeiten mit `pnpm add -w`, Pakete mit `pnpm --dir <paket> add` bzw. `--filter`. Workspace: Root, `packages/*`, `docs`, `prototypes/*`, ein Lockfile im Root. Neue Abhängigkeiten mit Build-Skripten müssen in `pnpm-workspace.yaml` unter `allowBuilds` freigegeben (`true`) oder geblockt (`false`) werden, sonst bricht `pnpm install` ab. Ausnahme: `e2e/` ist eine eigene pnpm-Workspace-Wurzel (`e2e/pnpm-workspace.yaml`, `e2e/pnpm-lock.yaml`) und wird auf dem Mac installiert; dort keine App-Abhängigkeiten.
- Beträge nie als `float` (`DECIMAL` in der DB, `Brick\Math\BigDecimal` in PHP, Strings im JSON). Primärschlüssel ULID (`HasUlids`).
- UI-Texte nur über Schlüssel in `lang/en.json` und `lang/de.json` (flach, Punkt-Namensräume wie `login.submit`, Platzhalter `:name`, Plural `.one`/`.other`). PHP `__('key')`, React `t('key')`/`tn('key', n)` aus `resources/js/lib/i18n.ts`, Admin-URLs im Frontend immer über `path('/…')`. `tests/Unit/TranslationsTest.php` prüft gleiche Schlüssel und dass jeder im Code benutzte Schlüssel existiert. Code und Kommentare Englisch.
- Gestaltung nach `prototypes/clickdummy-v2/DESIGN.md`. Tokens in `resources/css/app.css`: Rohwerte als CSS-Variablen (`:root` und `:root[data-theme='dark']`), Tailwind-Namen über `@theme inline` (`bg-surface-2`, `text-muted`, `shadow-float`, `rounded-lg` = 18 px, `text-sm` = 13 px, `h-control`, `font-strong`/`font-heading`, Breakpoints `xs` 520/`sm` 720/`md` 900/`lg` 1100). Tailwinds Farbpalette ist entfernt (`--color-*: initial`). Zahlen mit der Utility `num` (proportional), nie `tabular-nums`. Keine shadcn-Defaults, Radix nur für Dialog/Menü/Popover.
- UI-Datenfluss: Inertia-Props nur für Seitenkontext und serverseitig berechnete Kennzahlen (`App\Support\Overview`, `App\Support\DocumentQuery::counts/summary`); Listen und Details lädt die UI per SWR aus `/api` (`resources/js/api/*`, Schlüssel = URL), geschrieben wird nur über `lib/api.ts` → `/api` → Actions. Im Browser wird nie mit Beträgen gerechnet (`formatMoney` formatiert die API-Strings exakt).
- Seiten mit Shell setzen `Page.layout = appLayout` (`resources/js/layouts/app-shell.tsx`); neue Navigationspunkte in `resources/js/layouts/nav.ts`.
- Demo-Daten und Test-Beispiele nur fiktiv (`@example.com`, Studio Nordlicht, Hafenkontor Lindqvist, …); keine echten Firmen, Hosts oder Personen.
- CI: Pflicht-Job `tests` in `.github/workflows/tests.yml` – Name nie ändern. Neue Prüfungen dort anhängen. Weitere Jobs (kein Pflicht-Check): `einvoice`, `e2e` (Playwright gegen den Compose-Stack), `image` in `docker.yml` (bei PRs, die das Image ändern, nur Build amd64+arm64; bei Tags Push + Release). `docs.yml` veröffentlicht die Doku bei Änderungen in `docs/` auf `main` nach GitHub Pages (`https://openbill.dev`, eigene Domain in den Pages-Einstellungen des Repos). Dependabot (`.github/dependabot.yml`) für Actions, Composer, pnpm – nicht für Docker-Images (Digests, `DockerSetupTest`).
- Git: Branch je Änderung (`feat/…`, `fix/…`, `docs/…`; die Phasen-Branches `phase-NN-*` sind abgeschlossen), PR gegen `main`, Conventional Commits. Release: Tag `vX.Y.Z` nur nach Freigabe durch den Maintainer, vorher Abschnitt `### X.Y.Z` in `docs/en/upgrading.md` und `docs/de/upgrading.md`.

## Architektur

- Routen (`routes/web.php`): Admin unter Sprachpräfix `/{locale}` (`en|de`): `GET|POST /{locale}/login` (guest), `POST /{locale}/logout`, `GET /{locale}` = Übersicht (Routenname `home`, `OverviewController`), `GET /{locale}/documents` (`DocumentController@index`, Filter `?type&status&customer_id&q&date_from&date_to`, normalisiert über `DocumentQuery::lenient`), `GET /{locale}/documents/{id}` = Dokument-Editor (`DocumentController@show`, Props `document_id` + `context` aus `App\Actions\DescribeDocumentPage`), `GET /{locale}/customers`, `/customers/new`, `/customers/{id}` (`CustomerController`; IDs `whereUlid`), `GET /{locale}/templates`, `/templates/{id}` (`TemplateController`), `/fields?scope=` (`FieldController`, unbekannte Ebene → `document`), `/settings` → `/settings/organization`, `/settings/{section}` (`SettingsController::SECTIONS` inkl. `api`, eine Inertia-Seite `settings/show`, Props `section`, `can_manage_users`, `mcp_url`, `api_docs_url`); Gast: `GET|POST /{locale}/invitations/{invitation}` (`signed:relative`, POST zusätzlich `throttle:10,1`, `InvitationController`). `/` und `/login` leiten in die zuletzt genutzte Sprache um (Cookie `locale`, sonst `en`). Unbekanntes Präfix → 404.
- `app/Http/Middleware/SetLocale.php`: Sprache aus Präfix, sonst Cookie, sonst `en` (nie `Accept-Language`). Setzt `URL::defaults(['locale' => …])` und das Request-Attribut `locale`, merkt die Sprache im Cookie und **entfernt den Routenparameter `locale`**, damit Controller ihn nie als Argument bekommen (sonst verrutschen Model-Bindings). `SetLocale::fromRequest()` funktioniert auch vor der Middleware (Auth läuft wegen der Middleware-Priorität früher) und wird in `bootstrap/app.php` für `redirectGuestsTo`/`redirectUsersTo` genutzt.
- `app/Http/Middleware/HandleInertiaRequests.php`: Shared Props `locale`, `translations` (ganze JSON-Datei der Sprache), `auth.user` (`id`, `name`, `email`, `role`), `org` (`name`; nur angemeldet). TS-Typ: `SharedProps` in `resources/js/types.ts`. Sprachwechsel lädt die Seite neu (`resources/js/app.tsx`).
- **UI** (`resources/js`): `lib/api.ts` (fetch mit Session, `X-XSRF-TOKEN` aus dem Cookie, `Accept-Language`, `ApiError` mit Problem Details, 419 → `/sanctum/csrf-cookie` und einmal wiederholen, 401 → Login), `lib/swr.tsx` (`ApiProvider` in `app.tsx`), `api/*` (Typen, Schlüssel, `usePagedList` mit „Mehr laden“, Hooks), `components/ui` (Komponentenset), `layouts` (`AppShell` mit `NewDocumentProvider` und `Toaster`, Taste N), `lib/theme.ts` (Theme in `localStorage` `openbill:theme`, Inline-Skript in `app.blade.php` setzt `data-theme` vor dem Paint – beide Regeln gleich halten), `lib/toast.ts`, `lib/format.ts`, `lib/customers.ts`.
- `App\Support\DocumentQuery` (Filter der Dokumentliste für API und Seite, Status `overdue` = offene Rechnung mit `due_date` < heute), `App\Support\Overview` (Kennzahlen/Aufmerksamkeit/zuletzt bearbeitet, offene Beträge je Kunde; `build()` ist auch das MCP-Tool `get-overview`), `App\Support\Amount` (SQL-Summe → `"0.00"`).
- Login: `app/Http/Requests/LoginRequest.php` sperrt nach 5 Fehlversuchen je `lower(email)|IP` für 60 s; Route zusätzlich `throttle:20,1` je IP. Remember-Cookie nur mit Checkbox „Angemeldet bleiben“ (`remember`). Nach Login zurück zur angefragten Seite (nur Ziele auf der eigenen Basis-URL), aber in der Sprache des Logins.
- Nutzer: ULID, `role` (`App\Enums\UserRole`: `owner`/`member`), `locale` (nullable). `php artisan app:ensure-admin` liest `config('openbill.admin.*')` (= `ADMIN_EMAIL`/`ADMIN_PASSWORD`), legt einmalig einen Owner an, ändert bestehende Konten nie, überspringt ohne Variablen, bricht bei ungültiger E-Mail oder Passwort < 8 Zeichen ab.
- Gotenberg: `config('services.gotenberg.url')` (`GOTENBERG_URL`, DDEV: `http://gotenberg:3000`), `config('services.gotenberg.timeout')` (`GOTENBERG_TIMEOUT`, 20 s).
- **Domain** (`app/Domain`, reines PHP, nur `App\Enums` + brick/math, kein float – `tests/Unit/NoFloatTest.php`, `ArchTest`): `Money/Decimal`, `Tax/*`, `Totals/TotalsCalculator` → `Totals` (`toArray()` mit Strings), `Numbering/NumberFormatter`, `Lifecycle/StatusMachine`, `Fields/*` (Registry, `KeySlugger`, `CustomValueValidator`, `FieldDefinitionValidator`), `Compliance/ComplianceChecker` (Profile `basic`/`en16931`), `Conversion/DocumentConverter`. Port der Logik aus `prototypes/clickdummy-v2/src/domain`; Meldungen kommen als Codes (`ComplianceRule`, `FieldErrorCode`), übersetzt über `compliance.*` / `fields.error.*`.
- **Actions** (`app/Actions`, final, `handle(Actor $actor, …)`): einzige Stelle, die Fachdaten schreibt. Validieren selbst (Laravel-`ValidationException` mit Punkt-Pfaden wie `groups.0.positions.1.custom.ticket`), laufen in Transaktionen, schreiben `document_events` über `App\Support\EventLog`. Liste und Signaturen: Phasenplan `docs/superpowers/plans/2026-10-11-phase-02-domain.md`, Abschnitt „Interfaces“.
- **Support** (`app/Support`): `Actor` (user/token/system), `SnapshotBuilder` (Stammdaten in Snapshot-Form), `DocumentInspector` (Summen/Prüfung: Entwurf live, abgeschlossen aus dem Snapshot), `DomainMapper` (Models → Domain-DTOs), `GroupWriter` (ersetzt Gruppen/Positionen, behält eigene IDs), `Text::t()` (`__()` mit String-Rückgabe).
- **Sperre:** `Document::updating/deleting` werfen `DocumentLockedException`, sobald `finalized_at` gesetzt ist (erlaubt bleiben `status` außer `draft`, `paid_at`, `cancelled_by_id`); Gruppen/Positionen prüfen über `Document::assertDraft()` altes und neues Dokument (kein Umhängen), eine Position muss in einer Gruppe ihres Dokuments liegen. Snapshots, Dateien und Events sind unveränderlich. Zusätzlich MariaDB-Trigger (`2026_10_11_100250_create_document_lock_triggers.php`) auf `documents`, `positions`, `position_groups`, `document_snapshots`, `document_files`: Query-Builder-Schreibzugriffe enden in `QueryException` (`SQLSTATE 45000`, Meldung `openbill: …`). Abschließende/ändernde Actions laden das Dokument in der Transaktion mit `lockForUpdate` neu und prüfen dort (`UpdateDraft`, `DeleteDraft`, `FinalizeDocument`, `SetDocumentStatus`, `ConvertDocument`).
- **Abschließen:** `FinalizeDocument` in einer Transaktion: Zeile sperren → Prüfprofil (`ComplianceFailedException` mit Issue-Liste) → `AllocateDocumentNumber` (`lockForUpdate` auf `number_sequences`, überspringt belegte Nummern) → Summen → Snapshot → Storno setzt Rechnung auf `cancelled` → `App\Contracts\DocumentArchiver` (`PdfDocumentArchiver`: PDF/XML ins Archiv; `NullDocumentArchiver` nur für Tests) → Event. Jeder Fehler rollt alles zurück.
- **Rendering** (`app/Rendering`): `ContextBuilder::build(Document, $sources)` → Liquid-Kontext (org, customer, contact, document, groups, positions; Beträge als Strings, eigene Felder direkt am Objekt, nur reservierte Kernschlüssel) + `Totals`. Quellen: gespeicherter Entwurf (`SnapshotBuilder::build`), abgeschlossen (Snapshot), ungespeicherter Entwurf (`DraftOverlay::apply` über `DraftInput::validate`, nie speichern), Beispieldaten (`SampleDataFactory`, Szenarien `RenderScenario`). `LiquidRenderer::render(TemplateSource, $context, RenderOptions)` → `RenderResult{header, body, footer, paper, errors[]}` (drei eigenständige HTML-Dokumente wie für Gotenberg; wirft nie wegen des Templates; `RenderError{part, line, message}` mit `RenderPart::file()`). Sandbox: `Liquid/LiquidEnvironment` (strikte Filter, Fehler mit Zeile, `ResourceLimits` aus `config('openbill.rendering')`, `BoundedForTag`, kein `tablerow`/`render`), Filter in `Liquid/OpenbillFilters` (`money`, `number`, `date`, `nl2br`, `t`). Vorschau-Schnittstelle: `App\Actions\RenderPreview` → `PreviewResult::toArray()` = Antwort von `POST /api/render`.
- **PDF und Archiv:** `GotenbergClient::pdf(RenderResult, ?xml)` (gotenberg-php baut den Request, Laravel `Http` sendet ihn mit `services.gotenberg.timeout`). `PdfDocumentArchiver` (gebunden an `DocumentArchiver`) rendert beim Abschließen aus dem Snapshot über `DocumentRenderer` und speichert per `PdfArchive` auf der Disk `archive` (`storage/app/archive/{yyyy}/{id}.pdf|xml`, `document_files` mit SHA-256): erst `.tmp/`, dann in der Transaktion umbenennen, `DB::afterRollBack()` löscht. Downloads: `DocumentPdf` (abgeschlossen: Archivdatei mit SHA-256-Prüfung, sonst `ArchiveCorruptedException`; Entwurf: live mit Wasserzeichen), `DocumentXml` (nur archivierte E-Rechnungen, sonst `ActionNotAllowedException` `no_e_invoice`).
- **E-Rechnung** (`app/EInvoice`): `CiiBuilder::build(Document, $sources, Totals)` mit horstoeko (Profil EN 16931, Storno = Gutschrift 381 mit positiven Beträgen), prüft gegen das XSD (`CiiBuilder::validate()`, sonst `EInvoiceInvalidException`). Einbetten macht Gotenberg (`pdfa=PDF/A-3b` + `facturX`, Datei `factur-x.xml`). Einzige float-Stelle: `CiiAmount::of()` (Rundreise-Prüfung).
- **Templates:** Paketformat `TemplatePackage` (`manifest.json`, `template.liquid`, `header.liquid`, `footer.liquid`, `styles.css`, `assets/…`), Prüfung `ManifestValidator`, Actions `ImportTemplatePackage` (ZIP, Assets auf Disk `local` unter `templates/{id}/`), `ExportTemplatePackage`, `SyncBuiltInTemplates` (Quellen `resources/templates/{klar,kante,leise}`, Migration `2026_10_11_100400`, `DemoSeeder`, `app:sync-templates`). Welches Template: `TemplateResolver::for()` (Dokument → Dokumenttyp → `klar`); der Snapshot friert das tatsächlich benutzte ein.
- **Exceptions** (`app/Exceptions`, Basis `DomainActionException::status()`): `DocumentLockedException` 409, `ActionNotAllowedException` 409 (`reason`), `ComplianceFailedException` 422 (`toArray()` → `[{path, message}]`).
- **Exceptions** zusätzlich: `TemplateRenderFailedException` 422 (`toArray()` = Fehlerliste), `EInvoiceInvalidException` 422, `PdfRenderFailedException` 503, `ArchiveCorruptedException` (kein Domain-Fehler, 500).
- `document_snapshots.data` enthält zusätzlich `legal_notes` (`small_business`, `reverse_charge`, `third_country` in der Dokumentsprache); `DocumentInspector` nimmt sie bei abgeschlossenen Dokumenten aus dem Snapshot und wirft `LogicException`, wenn einem abgeschlossenen Dokument der Snapshot fehlt. `document_events.user_id` hält den Nutzer hinter einem Token.
- **Grunddaten** kommen aus der Migration `2026_10_11_100300_insert_default_master_data.php` (Organisation, Dokumenttypen, Nummernkreise `Q`/`OC`/`INV`/`CN`, Steuersätze, Einheiten), nicht aus Seedern.
- **REST-API** (`/api`, Doku `docs/*/api.md`): DTO-Ressourcen in `app/ApiResource` (nie Eloquent-Models als Ressource), lesen über `app/State/Provider` (Eloquent → DTO, `fromModel()`), schreiben über `app/State/Processor` mit `read: false, deserialize: false`: der rohe JSON-Body (`App\Http\Api\RequestBody`) geht unverändert an genau eine Action. Dateien und fertige Action-Ergebnisse (PDF/XML, Paket-ZIP, `POST /api/render`, `render/sources|schema`, `position-suggestions`, signierte Downloads) sind Controller in `routes/api.php` (`app/Http/Controllers/Api`), im OpenAPI-Dokument über `App\OpenApi\OpenApiFactory`. JSON-Schlüssel snake_case (`name_converter => null`), leere Objekte als `ArrayObject` + `preserve_empty_objects`.

## Fallstricke

- `public/hot` bleibt liegen, wenn Vite hart beendet wird; dann lädt die Seite Assets vom toten Dev-Server. `rm public/hot`.
- `ddev exec` reicht die Argumente an eine Shell im Container weiter: Globs wie `./prototypes/*` werden dort expandiert. Den ganzen Befehl in einfache Quotes setzen: `ddev exec 'pnpm --filter "./prototypes/*" test'`.
- Tests laufen ohne Vite-Build (`withoutVite()` in `tests/TestCase.php`); Inertia-Tests prüfen, dass `resources/js/pages/<name>.tsx` existiert.
- Sessions sind JSON-serialisiert (`config/session.php`, `serialization => json`): Nach einem Test-Request liefert `session('errors')` ein Array, erst `->assertSessionHasErrors()` macht daraus wieder einen `ViewErrorBag`. Fehlertexte also nach `assertSessionHasErrors()` lesen.
- `phpunit.xml` erzwingt `DB_DATABASE=testing` (DDEV-Hook legt sie bei `ddev start` an; in CI der MariaDB-Service).
- Tailwind scannt nur `resources/` (`@import 'tailwindcss' source(none)` + `@source`), sonst landen Klassen aus Prototypen und Doku im CSS.
- `personal_access_tokens` ist eine eigene Migration (`2026_10_11_100600`, ULID-Schlüssel, `ulidMorphs('tokenable')`, `template_id`); Sanctum 4 bringt keine eigene mehr mit. Token-Model ist `App\Models\PersonalAccessToken`.

- serversideups Entrypoint führt `/etc/entrypoint.d/*.sh` in einer Subshell aus: `export` erreicht PHP-FPM nicht. `APP_KEY` kommt nur über den Config-Cache (`php artisan optimize` am Ende des Skripts) zu FPM – geänderte Umgebungsvariablen wirken erst nach `docker compose up -d` (neuer Container, neues `optimize`).
- Trusted Hosts sind außerhalb von `local`/Tests aktiv: Wer den Stack per `127.0.0.1` statt über den Host aus `APP_URL` anspricht, bekommt 400. Der e2e-Stack nutzt deshalb `APP_URL=http://localhost:7739`.
- Neues Basis-Image oder neue Version: Digest mit `docker buildx imagetools inspect <image:tag>` holen und **alle** Stellen gleich ändern (`DockerSetupTest`). `docker/metadata-action` taggt Vorabversionen (`v0.2.0-rc.1`) nur mit der vollen Version, nie `latest`.
- Neue Workspace-Pakete (`packages/*`, `prototypes/*`) brauchen eine eigene `COPY …/package.json`-Zeile in der Node-Stage des `Dockerfile`, sonst scheitert `pnpm install --frozen-lockfile` im Image-Build.
- `dockerhub.yml` überspringt den README-Sync, solange `baeroe/openbill` auf Docker Hub nicht existiert (vor dem ersten Release); nach einem Release läuft er per `workflow_run`.
- Laufzeit-Abhängigkeiten gehören nach `require`, nicht `require-dev`: Das Image installiert `--no-dev` (z. B. `phpdocumentor/type-resolver` für API Platforms `PhpStanExtractor`; fehlt es, scheitert `package:discover` im Image-Build).
- Veröffentlichte Ports kommen je nach Docker-Setup (Colima, Docker Desktop, rootless, docker-proxy) mit der Gateway-IP `172.x.0.1` im Container an, die in den Standard-Proxys liegt: Wer den Port erreicht, kann `X-Forwarded-*` setzen. Deshalb bindet Compose standardmäßig an `127.0.0.1` (`OPENBILL_BIND`), und wer ihn öffnet, schränkt `TRUSTED_PROXIES` auf den Proxy ein (Doku `reverse-proxy`).
- `.env.docker.example` lässt `ADMIN_PASSWORD`, `DB_PASSWORD`, `DB_ROOT_PASSWORD` absichtlich leer: Compose bricht per `${…:?}` ab, bis sie gesetzt sind (`DockerSetupTest`). Abschnitte in `docs/*/upgrading.md` werden zu GitHub-Release-Notizen: nur absolute Links (`ReleaseNotesTest`).
- Actions, die Secrets sehen (`docker/login-action`, `docker/build-push-action`, `peter-evans/dockerhub-description`), sind per Commit-SHA mit Versionskommentar gepinnt; Workflows haben `permissions: contents: read`, nur der Job `release` in `docker.yml` darf schreiben.
